# Emulator Test 7: texture directory recovery

Test 6 reached the animated menu and Single Player loading on the Android 9 x86 Google APIs emulator. The Test 6 log confirms repeated cache-root recovery. During loading step 6, four TGA requests failed under `files/qata/3d/textures/`. The supplied original cache has all four exact basenames under `files/data/3d/textures/` and has no `qata` root. The ARM translator then aborted with `Memory exhausted: requested 131072 bytes`. Thousands of failed thread-creation attempts preceded that abort, so the missing textures are not established as its cause.

Test 7 adds a separate fallback in the Storm `fopen` import guard. Only after an `r` or `rb` open fails, it changes `qata` to `data` for a flat `.tga` file under the exact Android app-cache `3d/textures` directory. It retries the open and logs `DH2FileGuard recovered texture path:` only on success. Paths outside that directory, nested texture paths, other extensions, writes, ordinary `data` paths, and existing successful opens are unaffected. The Test 6 repeated-root and directory guards remain.

The host C11 regression test checks all four observed paths and negative cases. It passes with `-Wall -Wextra -Werror`. NDK r29 compiles the ARM32 guard with the same warnings treated as errors. `patch_storm.py` verifies original library hashes, the pinned patch site, executable segment capacity, and absence of runtime data relocations. The generated unsigned APK passes ZIP CRC and library-hash verification.
